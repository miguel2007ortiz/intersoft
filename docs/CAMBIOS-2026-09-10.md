## Invariantes verificadas

- **Multi-tenant**: todo query set relevante sigue filtrado por `empresa` del
  perfil autenticado; ningún fix de esta ronda tocó el filtrado por tenant.
- **`select_for_update()` en dinero/stock**: los flujos de venta, checkout,
  ajuste de inventario y anulación siguen bloqueando `Producto`/`Venta`/
  `Empresa`/`Carrito` dentro de `transaction.atomic()`; los fixes #5, #6 y
  #12 refuerzan este patrón (checkout reordenado y `numero_factura`
  autobloqueado) en vez de debilitarlo.
- **`PASARELA_MOCK`/`DIAN_MOCK` por defecto**: el reordenamiento del checkout
  (#5) y el ajuste del adaptador DIAN (#2) no cambian el valor por defecto de
  esos flags; producción sigue exigiendo la config real explícita.
- **Contrato de error `{codigo, detalle, errores}`**: verificado end-to-end
  tras #9/#10 — todo error controlado y el fallback no controlado devuelven
  esa forma; el frontend (`django-error.util.ts`) ya toleraba variaciones,
  no requirió cambios.

## Rollback

Revertir en orden inverso al de aplicación (el más reciente primero), con
`git revert <hash>` sobre cada commit de fix (no usar `reset` en una rama ya
pusheada):

```
git revert 197ba99   # #13 ESLint frontend
git revert b1a2ca0   # #12 numero_factura
git revert 9eee239   # #9 + #10 contrato de error
git revert 6aa83bd   # #8 estadisticas de ventas
git revert fcc873f   # #5 + #6 checkout / carrito
git revert f03b3b5   # #4 RBAC
git revert 17c1d0a   # #2 + #3 DIAN / nota credito
git revert 75dbc90   # #1 + #11 XSS / CSV injection
```

Cada commit es independiente y toca archivos distintos o secciones
puntuales del mismo archivo, así que revertir uno solo (por ejemplo, si algo
de #12 causa un problema no previsto) no debería arrastrar a los demás.
